# 影视库海报墙 · MediaLibrary

一个跑在本机的 Web 媒体库：扫描视频目录 → 联网刮削海报/简介 → 海报墙展示 → 点击用迅雷影音播放。
**零第三方依赖**，整个目录拷到另一台机器即可运行。

---

## 快速开始

1. 双击 `run.bat` —— 会自动打开浏览器（控制台里也会打印真实访问地址）
2. 点右上角「增量更新」

首次启动会自动生成 `config.json` 和 `data/library.db`。

> `run.bat` 按 `runtime\python.exe` → `py -3` → `python` 的顺序找解释器，找到就启动。
> 默认端口 8000，被占用时自动顺延到 8010，**以控制台打印的地址为准**。
> 关闭控制台窗口即停止服务。

---

## 环境要求

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11（其它系统可运行，但播放器探测只针对 Windows） |
| Python | 3.9 及以上 |
| 播放器 | 迅雷影音 `xmp.exe`（推荐）、PotPlayer、VLC 任选其一 |

**目标机器没有 Python？**
下载 [Windows embeddable package](https://www.python.org/downloads/windows/)（3.9+，amd64），解压后把 `python.exe` 等文件放进本目录下的 `runtime\` 文件夹，`run.bat` 会优先使用它，实现零安装运行。

---

## 换一台机器怎么用

整个 `MediaLibrary` 目录直接拷贝即可，**不需要改代码**：

- 数据库只存**相对路径**，绝对路径在运行时用「媒体库根目录 + 相对路径」拼出来
- 播放器路径不写死，启动时自动探测（自定义 → 迅雷影音 → PotPlayer → VLC → 系统关联）
- 海报缓存按内容寻址命名（`tmdb_680.jpg` / `douban_xxx.jpg`），换库换机器都能复用

**一键安装（Windows）**：直接双击根目录的 `install.bat`，应用会安装到
`%LOCALAPPDATA%\MediaLibrary` 并在桌面创建带图标的快捷方式，安装完可选立即启动。
升级重装不会覆盖已有的 `data\` 用户数据和 `config.json` 个人配置。

到新机器后，如果媒体库路径变了，进「设置 → 媒体库」把路径改掉即可，历史刮削数据全部保留。

## 配置说明

`config.json` 关键项：

```jsonc
{
  "server": { "host": "0.0.0.0", "port": 8000 },   // 0.0.0.0 允许局域网访问
  "tmdb": {
    "base_url": "https://api.tmdb.org/3",           // 国内必须用这个域名
    "api_key": "你的 key",
    "language": "zh-CN"
  },
  "player": {
    "chain": [],                                     // 留空自动探测
    "allow_remote_play": false                       // 是否允许远程设备触发本机播放
  },
  "scan": {
    "min_size_mb": 20,                               // 小于此体积的"花絮/预告"类文件直接跳过
    "max_depth": 6,                                  // 递归深度上限
    "exclude": ["花絮", "剧集\\亚洲", "*.ts"]         // 排除规则，见「排除规则」一节
  },
  "poster": {
    "web_search": true                               // TMDB/豆瓣都没有海报时，用图片搜索兜底
  },
  "llm": {
    "enabled": false,                                // LLM 兜底，见「LLM 兜底」一节
    "base_url": "https://api.openai.com/v1",
    "api_key": "", "model": ""
  },
  "super_series": [],                                // 自定义大系列，见「大系列」一节
  "seed_library": { "path": "\\\\NAS\\电影" }        // 仅首次启动用于初始化
}
```

### 关于 TMDB 域名

`api.themoviedb.org` 在中国大陆通常**不可达**，但官方备用域名 `api.tmdb.org` 可用，程序默认就用它。
如果以后连 `api.tmdb.org` 也访问不了，把 `base_url` 换成你自己的反代地址即可。

### 申请 TMDB API Key

1. 打开 <https://www.themoviedb.org/signup> 注册
2. 进入 设置 → API → 申请开发者 Key（免费）
3. 复制 **API Key (v3 auth)** 的 32 位字符串，填到「设置 → TMDB」

Key 未填时程序照常运行，会降级为豆瓣海报 + 本地占位图。

## 使用说明

### 增量更新

点「增量更新」只处理变化：

- 新文件 → 加入并刮削
- 删除的文件 → 从库中移除（软删除，连续两轮确认后才彻底清理）
- 改名的文件 → 按体积+文件名相似度识别，**保留原有刮削结果，不重新刮削**
- 已有条目 → 直接跳过（`scrape_task` 主键 + `status='ok'` 双重短路）

### 移除条目

- **单条**：卡片悬停点左上角垃圾桶，或详情页底部「从媒体库移除」
- **批量**：顶栏「选择」→ 勾选（支持全选/反选）→「移除所选」

> ⚠️ 移除**只删媒体库记录，绝不删除磁盘上的视频文件**。
> 移除的文件会写入屏蔽名单（`ignored_path`），下次扫描不会复活。
> 需要恢复时到「设置 → 已移除的条目」点「恢复」。

### 排除规则（把不想看到的东西挡在海报墙外）

「设置 → 排除规则」里可以按目录或文件批量排除，不用逐个去点移除。

支持三种写法（大小写不敏感，正反斜杠都行）：

| 写法 | 含义 | 例子 |
|---|---|---|
| 目录前缀 | 以该目录开头，整棵子树都排除 | `剧集\亚洲`、`圆桌派1-7季` |
| 通配 | `*` `?` 匹配任意层级 | `*.ts`、`第*集`、`剧集\*预告*` |
| 段内通配（不含 `\`） | 对路径的**每一段**分别匹配 | `*幕后花絮`、`*预告片` |
| 纯文字 | 没有分隔符也没有通配时，路径**包含**该串即排除 | `花絮`、`sample` |

### 慎用纯文字规则

纯文字规则最省事，但它是"包含"语义，会连带命中同名的**上层目录**：

```
末代皇帝 4K [内含最全完整幕后花絮]The Last Emperor (1987)[BDrip]...
   ├─ 幕后花絮\菜单.mkv          ← 想排除的
   ├─ 预告片\xxx.mkv
   └─ 正片\末代皇帝.mkv           ← 不想排除，但路径里同样有"幕后花絮"
```

这种结构填 `花絮` 会把整个《末代皇帝》都排掉。改用**段内通配** `*幕后花絮`
只匹配"以幕后花絮结尾的某一段目录/文件"，`正片`、`预告片` 不受影响。

当前库里的实际配置：

```jsonc
"exclude": ["fromX", "圆桌派1-7季", "*幕后花絮"]
```

补充说明：

- 想只排除某个子目录，写成带路径前缀的形式（`剧集\亚洲`）更精确
- 改完点「保存」再点「增量更新」才会生效；被排除的条目会从库里移除
- 排除规则**不会删磁盘文件**，只是不扫它
- 加规则导致文件数骤降时不会触发"共享盘掉线"保护（安全阀会先扣掉被排除的部分再比对）
- 被排除的条目走的是两轮确认：第一次增量只标记，**第二次增量才真正删除**。
  这样共享盘瞬时抖动不会把条目和已刮削的元数据一次性清空
- 运行中手工编辑 `config.json` 也会自动生效（按文件修改时间重载，不用重启服务）

### 排序

顶栏右侧「排序」下拉 + 方向按钮，7 个排序键：

| 排序键 | 说明 |
|---|---|
| 加入时间 | 最近加入的在前（默认） |
| 文件修改时间 | 按视频文件在磁盘上的 `mtime` |
| 评分 | TMDB 评分，没评分的排最后 |
| 名称 | 按中文拼音排序 |
| 年份 | 上映年份新的在前 |
| 体积 | 文件总大小，只累计未删除的文件 |
| 集数 | 剧集类按集数，其他为 0 |

方向按钮切换升/降序（↑↓）。排序对系列卡同样生效：
系列卡按成员的聚合值参与排序（取成员里最新加入/最大体积的那个），
同系列的多部不会被打散。

「按修改时间」和「按体积」只在条目有未删除文件时才有值；
`data` 目录下的数据库会为每个条目预聚合 `last_mtime` / `total_bytes`，
不用每次查文件表。

### 按类型筛选

海报墙上方有一条类型筛选条（剧情 / 动作 / 喜剧 / 恐怖 / 战争 …），点一下就只看这一类，
再点「全部类型」取消。数字是当前库里属于该类型的条目数，按数量从多到少排。

类型来自 TMDB 的 `genres`，刮削时一起入库；没识别出来的条目没有类型，不参与筛选。

### 系列合集（哈利波特 / 007 / 圆桌派）

同一系列的多部作品会折叠成**一张系列卡**，点进去才看到每一部的海报。

两条归组规则：

| 来源 | 适用 | 说明 |
|---|---|---|
| TMDB `belongs_to_collection` | 电影 | 哈利波特、007、指环王、星球大战、漫威各分支等，最准 |
| 去季号同名基名 | 剧集 | TMDB 没有"合集"概念，把「圆桌派 第一季 / 第二季 …」按去掉季号的基名归到一起 |

- 只有 **≥2 个成员**才建系列，单片不会变成系列卡（大系列除外，见下）
- 系列封面优先用 TMDB 的合集海报，没有就用第一个成员的海报
- 顶栏的「系列」按钮只看系列卡
- 系列归组在每次同步的最后一步自动重算，也可以手动触发：
  `POST /api/franchises/rebuild`

### 大系列：漫威超英电影（含子系列）

第三条归组规则是**用户自定义大系列**：把若干子系列 / 单片收进一个总系列，
打开总系列后再按子系列分节展示。比如「漫威超英电影」里再分钢铁侠、雷神、美国队长……

```jsonc
"super_series": [
  {
    "name": "漫威超英电影",
    "children": [
      { "name": "钢铁侠系列",
        "collection_ids": [131292],                    // TMDB 合集 ID，最准
        "keywords": ["Iron Man", "钢铁侠"] },           // 标题/原名包含即命中也
      { "name": "浩克系列",
        "collection_ids": [],
        "keywords": ["Incredible Hulk", "无敌浩克"] }
    ]
  }
]
```

匹配规则（优先级从高到低）：`collection_ids` 精确命中 → `tmdb_ids` → `keywords` 文本包含。
一个条目只进第一个命中的大系列。

**注意：`keywords` 只拿 `title` 和 `original_title` 比对，故意不含 `collection_name`。**
TMDB 给《蜘蛛侠：英雄归来》的合集中文名叫「蜘蛛侠（复仇者联盟）（系列）」，
拿合集名做包含匹配会把它误分进复仇者联盟系列 —— 合集归属请一律用 `collection_ids`。

被收进大系列后，条目的 `franchise_id` 改指大系列、子系列名写在 `series_group` 字段；
原来的子系列卡会自动合并掉，不会在「系列」页重复出现。

`collection_id` 可以在 TMDB 网站的合集页面 URL 里看到，也可以直接查库：

```bash
python -c "import app.db as db; [print(r) for r in db.rows(
  'SELECT id,title,year,collection_id,collection_name FROM item'
  ' WHERE collection_id IS NOT NULL ORDER BY collection_name, year')]"
```

### LLM 兜底（可选，默认关闭）

只有 **TMDB（含跨语言重搜）+ 豆瓣都认不出**时才触发，典型场景是港台译名和
TMDB 官方译名完全无交集 —— 《007：你死我活》的港版叫《生死关头》，
任何从文件名派生的查询串都撞不上，得靠「007 系列第 8 部」这类外部知识搭桥。

```jsonc
"llm": {
  "enabled": false,                          // 手动打开
  "base_url": "https://api.openai.com/v1",   // 任意 OpenAI 兼容 /chat/completions
  "api_key": "sk-...",
  "model": "gpt-4o-mini",                    // DeepSeek / 通义 / 本地 vLLM 都行
  "timeout": 30
}
```

**安全约定（重要）**：LLM 只负责猜**候选搜索词**，绝不直接产出 TMDB ID 或元数据。
候选词仍要过一遍正常的 `client.search()` + 打分管线，分数低于 0.6 就照样判未识别。
所以即使模型编了一个热门片名，也不会把冷门条目强行认成它。

调用时机还有两道闸：条目没被 `locked`，且本次刮削任务还没重试过
（重试说明是网络/限流问题，不重复花钱）。未配置或 `enabled:false` 时完全不发请求。
Key 在「设置 → LLM 兜底」里填，返回给前端的配置会打码。

### 海报兜底：尽量不留白

刮削时按四级降级，前一级失败才走下一级：

1. TMDB 详情接口的 `poster_path`
2. TMDB `/images` 接口里**任意语言**的海报（有些片子只有英文/日文海报）
3. 豆瓣 `subject_suggest`（免登录）—— 专门救 TMDB 没有的国产剧、综艺
4. 图片搜索（360 图片 → 必应图片），只收竖版、够大、长宽比接近海报的图

第 4 级会做相关性过滤：标题里带「沙龙 / 招聘 / 模板 / 热线 / 二维码」这类词的活动海报、
横幅广告一律丢掉，专业影视图库（豆瓣、TMDB、IMDb、猫眼）的图加权。

> 实测效果：264 个条目，**无海报 0 个**。

### 片名灵活化

文件名里的修饰语经常让搜索落空（`给阿嬷的情书 潮汕话`、`无痛凯恩 无痛先生 无痛侠`）。
刮削前会生成一串**降级变体**逐个尝试，命中就停：

- 反复剥掉尾部修饰语：语言（潮汕话/国粤双语）、画质（1080p/4K）、版本（导演剪辑版/未删减）、季号（第八季）
- 剥掉尾部括号
- 按 `：` `——` 拆出主标题和副标题，两边都试
- 纯中文用空格并列的别名逐个试（`无痛凯恩 无痛先生 无痛侠` → 三个都试）

同时 TMDB 检索分三轮：**先把年份作为接口参数**（`365 Days` + year=2020 能精准命中
《黑帮大佬和我的365日》），再用纯文本查询兜底；前两轮都没拿到高置信结果时，
**换语言重搜第三轮**（zh-CN 只回中文标题，而 `original_title` 也可能是中文 ——
《96分钟：列车爆炸案》的 `original_title` 是繁体「96分鐘」，与英文文件名
`96 Minutes` 相似度只有 0.286，前两轮全被 `min_sim` 过滤掉，换 `en-US` 才能对上）。

打分上还有两条专门的修正：

- **标题完全一致时抬满 rank 权重**。TMDB 结果按热度排，《美国队长》搜索结果里
  排第 1 的是《美国队长3》（人气 35.4），第 2 名才是 2011 年的《美国队长》（17.6）。
  `sim` 1.0 vs 0.889 只差 0.05 分，`rank` 差 0.10 分，精确匹配反而输给续作
  （0.725 < 0.775）。现在 `sim >= 0.95` 时 `rank_score = 1.0`。
- **同分时按热度决胜**。同名的《美国队长》有 2011 和 1990 两版，`sim` 都是 1.0，
  靠 `popularity` 稳定地取到 2011 那一部。

### 刮错了怎么办

`item.year` 会被刮削结果覆盖，一旦刮错就会自我强化（拿错年份继续搜，越错越离谱）。
所以入库时另外存一份 `year_hint`（从文件名解析，永不覆盖），重刮时以它为准。

检查哪些条目"库里年份和文件名年份对不上"：

```bash
python -m tools.audit_matches          # 只看
python -m tools.audit_matches --fix    # 重置为待刮削，下次增量更新重刮
python -m tools.audit_matches --fix --run   # 重置并立刻同步
```

单个条目也可以在详情页点「重新刮削」，或「改绑 TMDB」直接指定 ID。

#### 刮成了**别的片子**：用「按文件名重刮」

「重新刮削」有个坑：它拿 `item.title` 当搜索线索，而 TMDB 命中错片时会把
错误片名写进 `title`（《美国队长》第一部 → "美国队长3"）、错误原名写进
`original_title`（→ "Captain America: Civil War"）—— 于是刷新多少次都还在
内战那部里打转。

详情页的**「按文件名重刮」**按钮会先按磁盘上的真实文件名重新解析一遍，
把 `title` / `original_title` / `year` 还原、清掉 `tmdb_id` / `collection_id`
等错误绑定关系，再重新刮削。等于回到唯一的真相来源。

对应接口：`POST /api/items/{id}/refresh` 带 `{"reset": true}`，
内部实现是 `sync.reset_item_from_files()`。

### 多个媒体库

「设置 → 媒体库」可以添加多个目录，顶部下拉切换：

| 场景 | 行为 |
|---|---|
| 切回已刮削过的库 | **秒开**，直接读缓存，不重新刮削 |
| 切换到新目录 | 全量扫描 + 全量刮削 |
| 点「重刮」 | 该库全部重新刮削（手动改绑过的条目除外） |

### 手动纠错

刮削错了？详情页点「改绑 TMDB」，输入 TMDB ID 或作品链接（如 `https://www.themoviedb.org/movie/680`），
改绑后该条目会被锁定（`locked=1`），之后的自动刮削永远不会覆盖。

刮成了**别的片子**用「按文件名重刮」（见上面说明）。

### 青少年模式（默认）

应用启动后默认进入**青少年模式**，适合家里读初中的孩子使用：
只显示经过过滤的影视条目，并隐藏设置、增量更新、选择、移除等管理入口。
界面上**不会显示任何「青少年模式」字样**，看起来就是一个普通的影视库。
成人模式需要密码，用户名 `sysadmin`，**初始密码 `changeme`**（登录框里不会提示初始密码）。

**进入 / 退出**

- 进入：**双击顶栏左侧的「🎬 影视库」标志**，弹出「家长验证」，输入密码即可。
- 退出：成人模式下顶栏右侧会出现一个不起眼的「退出」按钮；也可以再次双击标志，在弹窗里点「退出成人模式」。
- 登录状态只保存在服务进程内存里，**重启应用即回到青少年模式**（Cookie 最长 8 小时）。
- 连续输错 5 次密码会锁定 60 秒。

**修改密码**

「设置 → 青少年模式 → 修改密码」：输入原密码与新密码（至少 6 位）。
密码哈希存在数据库里，不写入 `config.json`，也不会出现在任何接口返回值中。

**默认过滤规则（标准档）**

一条内容在青少年模式被隐藏，满足任一条件：

| 条件 | 说明 |
|---|---|
| TMDB `adult` 标记 | 成人内容 |
| 分级命中 | `R` / `NC-17` / `TV-MA` / `18+` / `18` / `III` / `R18` / `R18+` / `X` |
| 类型命中 | 恐怖、恐怖片、惊悚、情色、色情、成人、血腥 |
| 标题敏感词 | 色情、情色、三级、成人版、无码 |

过滤在**服务端**完成：被隐藏的条目不会出现在 `/api/items`、系列列表、详情与播放接口里，
不会通过「看源代码 / 抓接口」绕过前端隐藏。
犯罪、战争、悬疑、动作等类型不自动屏蔽，交给分级（`R` / `TV-MA`）兜底，
避免把大量 PG-13 的正常影片一起藏掉。

**分级补全**

老库入库时没有存分级信息。成人模式下进入「设置 → 青少年模式」，
点「补全分级信息」联网从 TMDB 补一次（只更新 `adult` / `certification` 字段）。
补全前，类型与标题规则、人工屏蔽仍然生效。

**人工屏蔽 / 放行（成人模式）**

- 海报墙点「选择」→ 多选 →「屏蔽」/「取消屏蔽」。
- 详情页可对单条「屏蔽」；自动规则误判的条目可点「放行」让它重新出现在青少年模式。
- 屏蔽优先级高于放行；过滤只影响应用内浏览与播放，**不会移动或删除磁盘文件**。

**调整过滤强度**

不想用标准档时，手动编辑 `config.json` 的 `kids` 段：

```json
"kids": {
  "enabled": true,
  "blocked_genres": ["恐怖", "恐怖片", "惊悚", "情色", "色情", "成人", "血腥"],
  "blocked_certifications": ["R", "NC-17", "TV-MA", "18+", "18", "III", "R18", "R18+", "X"],
  "blocked_title_keywords": ["色情", "情色", "三级", "成人版", "无码"],
  "block_adult_flag": true
}
```

把 `enabled` 改成 `false` 会关闭模式区分（等同于一直成人模式）。

> **安全边界**：这是家长控制，不是安全沙箱。能直接读写 `data/library.db`
> 或 `config.json` 的孩子仍然可以绕过；也不防局域网内直接猜图片 URL。
> 目的是让日常使用简单、默认安全，而不是对抗技术型绕过。

## 常见问题

**Q: 大量条目显示「未识别」**
A: 文件名太乱（如纯时间戳）或 TMDB 搜不到。可在详情页「改绑 TMDB」手动指定。

**Q: 海报墙空白 / 图片裂开**
A: 检查 `data/cache/posters/` 是否有文件；确认能访问 `image.tmdb.org`。刮削失败时前端会显示本地生成的占位海报。

**Q: 提示「TMDB API Key 无效」**
A: 到「设置 → TMDB」重新填 Key。注意 v3 key 是 32 位十六进制，v4 token 是 JWT 长串，程序两种都支持（`auth_mode` 自动适配）。

**Q: 同步很慢**
A: 首次全量刮削约 380 个条目需要 3~6 分钟（TMDB 限速 3.5 请求/秒）。之后增量更新通常只要几秒。

**Q: 端口被占用**
A: 程序会从 8000 自动往后探测到 8010，实际端口看控制台输出。全部占用时会明确报错并提示改 `config.json` 的 `server.port`。

**Q: 双击 run.bat 报「'ython.exe' 不是内部或外部命令」之类**
A: `run.bat` 的换行符被改成了 LF，或编码被存成了 UTF-8。
cmd.exe 解析批处理**必须用 CRLF 换行**，用 LF 会让它读取位置错位、每行开头吃字；
再加上 UTF-8 中文会变乱码。修复方式：

```
# 在本目录执行（PowerShell / cmd 均可，需要已装 Python）
python -c "d=open('run.bat','rb').read().decode('utf-8');open('run.bat','wb').write(d.replace('\n','\r\n').encode('gbk'))"
```

或者用记事本打开 `run.bat` → 另存为 → 编码选 **ANSI** → 保存。
（`chcp 65001` + UTF-8 的写法在 cmd 里同样会错位，不要用。）

**Q: 播放没反应**
A: 确认是**在本机浏览器**点的播放；检查「设置 → 播放器」是否检测到播放器；迅雷影音是单实例程序，重复点击会在已有窗口里新开标签。

## 技术要点（给二次开发者）

- **分组幂等**：条目唯一键 `group_key`（电影=文件相对路径，剧集=目录+剧名 slug），重扫时按它 upsert，元数据不丢
- **增量三要素**：`rel_path_key`(lower) + `size` + `mtime`（SMB 有 2 秒精度，比较用 `abs(diff)>2`）
- **防重复刮削三把锁**：`scrape_task.item_id` 主键、`item.status='ok'` 短路、`item.locked=1`
- **安全阀**：扫描到的文件数 < 库内记录 50% 时自动中止，避免共享盘掉线把整库删掉
- **不改文件**：全项目没有任何删除磁盘文件的代码路径
